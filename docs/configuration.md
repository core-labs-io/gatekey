# Configuration reference

All Gatekey configuration is via environment variables — for docker-compose
deployments, set them in `.env` (copied from `.env.example`, or generated by
`setup.sh` / `setup.ps1`).

## Required

| Variable | Description |
|---|---|
| `GATEKEY_ADMIN_TOKEN` | Break-glass/bootstrap bearer token for the admin API/console. A permanent secondary auth path alongside SSO, keeping full Org Admin rights on every endpoint and screen. Audit entries record its actions as `system:admin_token`. |
| `GATEKEY_MASTER_KEY` | Base64-encoded 32-byte AES-256 key. Encrypts provider keys, team webhook URLs, and self-hosted-endpoint bearer tokens at rest. **Back this key up in a password manager or secrets vault — losing it makes every stored secret permanently unrecoverable.** |

## Optional

| Variable | Default | Description |
|---|---|---|
| `GATEKEY_REDIS_URL` | unset | Redis connection URL (`redis://<host>:<port>/<db>`) for rate limiting, response caching, and shared state. In docker-compose the working value is `redis://redis:6379/0` — and you must **also** start Redis with `docker compose --profile cache up`. Starting the profile without setting this URL runs a Redis container the backend never talks to. Unset = these features disabled (failover still works; it doesn't need Redis). |
| `GATEKEY_PUBLIC_API_BASE_URL` | `http://localhost:8000` | Browser-facing backend URL the frontend is built against — override if the console is accessed from somewhere other than `localhost`. |
| `GATEKEY_FRONTEND_ORIGIN` | `http://localhost:3000` | The console's browser origin — always in the CORS allowlist and the origin session cookies are exchanged with. Must be the exact real origin if the console isn't on `localhost:3000`: credentialed CORS (session cookies) forbids wildcards. |
| `GATEKEY_CORS_ALLOWED_ORIGINS` | unset | Comma-separated *additional* browser origins allowed to call the API. `*` entries are ignored (wildcards are incompatible with cookie auth). |
| `GATEKEY_PROVIDER_VALIDATION_TIMEOUT_SECONDS` | `8` | Timeout for the live validation call made when a provider key is entered. |
| `GATEKEY_TRUST_PROXY_HEADERS` | `false` | Trust `X-Forwarded-For`/`X-Real-IP` for audit source-IP capture. Only enable behind a reverse proxy that overwrites/strips these headers on the way in — a client-supplied header is otherwise fully spoofable. Leave unset for an instance exposed directly to the internet. |
| `DATABASE_URL` | set by `docker-compose.yml` | Postgres connection string (`postgresql+asyncpg://...`). Only needed manually for local (non-docker) backend development. |

### SSO (OIDC)

See [sso.md](sso.md) for the full walkthrough. The four `GATEKEY_OIDC_*`
variables are **all-or-none**: set all four or none (startup fails fast on a
partial set). Unset = SSO disabled and the SSO routes return 404.

| Variable | Default | Description |
|---|---|---|
| `GATEKEY_OIDC_ISSUER_URL` | unset | OIDC issuer base URL (discovery document is fetched from `<issuer>/.well-known/openid-configuration`). |
| `GATEKEY_OIDC_CLIENT_ID` | unset | OIDC client id registered at your IdP. |
| `GATEKEY_OIDC_CLIENT_SECRET` | unset | Confidential-client secret. Never logged; the Identity & Access screen reports only whether it is configured, never the value. |
| `GATEKEY_OIDC_REDIRECT_URI` | unset | Must exactly match the redirect URI registered at the IdP: `http(s)://<backend>/v1/auth/sso/callback`. |
| `GATEKEY_SESSION_COOKIE_SECURE` | `true` | `Secure` flag on the session cookie. Set `false` only for local plain-http dev — over http with the default, the cookie is never sent and SSO login silently fails. |
| `GATEKEY_SESSION_TTL_HOURS` | `12` | Session lifetime. |

### SMTP (budget threshold-alert email)

Webhook alerts need no server config (the URL is set per team on the team's
alert settings). Email alerts additionally need SMTP variables — leave them
all unset and the email notifier is a silent no-op (an informational log
line at startup, never an error), regardless of any team's email toggle.
If *any* `GATEKEY_SMTP_*` variable is set, `HOST` and `FROM_ADDRESS` become
required (startup fails fast otherwise).

| Variable | Default | Description |
|---|---|---|
| `GATEKEY_SMTP_HOST` | unset | SMTP server for threshold-alert email. |
| `GATEKEY_SMTP_PORT` | `587` | SMTP port. |
| `GATEKEY_SMTP_USERNAME` | unset | SMTP auth username (omit for unauthenticated relays). |
| `GATEKEY_SMTP_PASSWORD` | unset | SMTP auth password. |
| `GATEKEY_SMTP_FROM_ADDRESS` | unset | `From:` address on alert emails. |
| `GATEKEY_SMTP_USE_TLS` | `true` | STARTTLS on the SMTP connection. |

> Email delivery is implemented and unit-tested but has never been verified
> against a live mailbox — test it against your own SMTP relay before
> relying on it. Webhook delivery *is* the verified alert path. See
> [known-limitations.md](known-limitations.md).
